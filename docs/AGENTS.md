# 开发约定

给所有在本仓库工作的编码代理使用。

## 必须遵守

- 只在自己的功能分支上提交，通过 Pull Request 交付。不要推 `main`，不要合并 PR，不要部署。
- 不要把原站的文案、图片、Logo、协议正文、系统模板原文或站点地址写进仓库。
- 站名使用「GeoMix」占位，直到另有通知。
- 计费默认 SHADOW（只记账不实扣），保留切换到 STRICT 的开关。
- 新增配置项同步写进 `.env.example`，不要提交真实密钥。
- 每个 PR 要有单元测试；页面类 PR 附截图对照。
- 冲突约定：改 `packages/shared` 时，只追加自己模块的常量文件，不改别人的文件。

## 正常迭代与 CI 门禁流程

1. **分支与批次**：从最新的 `main` 拉出独立功能分支，按 [终版实现路线](./终版实现路线.md) 第 F05 节的批次与依赖关系推进。
2. **本地自检**：提交 PR 前必须确保 `pnpm lint`、`pnpm typecheck`、`pnpm test` 全部通过；涉及数据库或 Redis 的改动，需在对应环境下执行集成测试（`GEOMIX_DB_INTEGRATION=1` / `GEOMIX_REDIS_INTEGRATION=1`）并写明结果。
3. **CI 门禁（必须全绿）**：创建或更新 PR 后，必须确认 GitHub Actions（`lint, typecheck, test`）**全部通过**才能交接或请求合并；若 CI 失败，必须在当前分支修复至全绿，不得带红灯交接。
4. **PR 交付清单**：PR 描述中写明关联 Issue、变更范围、测试与 CI 状态，以及页面类 PR 的截图对照；仍由人工（或指定合并流程）统一审核合并，代理不直接向 `main` 推送或自行合并。

## 依据

实现以 [终版实现路线](./终版实现路线.md) 为准，已确认事项以 [decisions.md](./decisions.md) 为准。issue 里的验收标准必须全部满足。
