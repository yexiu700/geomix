# GeoMix 运维与部署手册（单机预发 / 生产）

本手册面向 GeoMix 平台维护者，覆盖单机预发环境一键部署、Nginx + HTTPS 反向代理配置、PostgreSQL 与 MinIO 全量备份及灾难恢复演练、完整环境变量说明（不含任何真实密钥），以及管理后台 LLM 成本日报的运维口径。

> **合规与安全红线**
> - 仓库内严禁提交填充了真实密钥的 `.env`、TLS 私钥或备份归档文件。
> - 默认计费策略固定为 `BILLING_MODE=SHADOW`（影子记账、不扣真实点数），仅在管理员明确验证无误后于后台按租户切换。
> - 一键部署与恢复脚本由维护者在目标宿主机执行，CI/编码代理仅运行 `--dry-run` 预检，不直接向外部生产环境发起部署。

## 1. 部署拓扑概览

[docker-compose.prod.yml](../docker-compose.prod.yml) 编排以下单机服务：

| 服务名 | 镜像 / 构建来源 | 端口暴露策略 | 职责说明 |
| --- | --- | --- | --- |
| `postgres` | `pgvector/pgvector:pg16` | 仅容器内网 `:5432` | 主业务数据库与 `pgvector` 1024 维品牌事实卡向量检索（`BrandFactChunk`） |
| `redis` | `redis:7-alpine` | 仅容器内网 `:6379` | BullMQ 异步队列、分布式租约心跳与登录/验证码/0 点 AI 动作限流 |
| `minio` / `minio-init` | `cgr.dev/chainguard/minio` | 仅容器内网 `:9000` | S3 兼容对象存储（品牌素材原图/缩略图、行内 AI 配图产物等），自动创建 Bucket |
| `migrate` | `ghcr.io/<owner>/geomix-server` | 一次性任务 | 启动前自动执行 `prisma migrate deploy` |
| `api` | `ghcr.io/<owner>/geomix-server` | `127.0.0.1:${API_PORT:-3001}:3001` | NestJS REST API（`/api/v1` & `/api/v2`），默认开启 `AUTH_TRUST_PROXY=true` |
| `worker` | `ghcr.io/<owner>/geomix-server` | 无端口暴露 | BullMQ 异步队列消费者（4 个队列：`fact-index`、`geo-batch`、`visibility-check`、`maintenance`） |
| `web` | `ghcr.io/<owner>/geomix-web` | `127.0.0.1:${WEB_PORT:-3000}:3000` | Next.js 前端应用（极简 5 工作区控制台与管理后台） |
| `nginx` *(可选)* | `nginx:1.27-alpine` (`--profile tls`) | `${NGINX_HTTP_PORT:-80}:80`、`${NGINX_HTTPS_PORT:-443}:443` | 容器化 HTTPS 反向代理，基于 [geomix.conf.template](../docker/nginx/geomix.conf.template) |

## 2. 单机预发环境一键部署步骤

### 2.1 宿主机准备

1. Linux x86_64/arm64（建议 Debian 12 / Ubuntu 22.04+，4C8G 及以上，磁盘可用 ≥ 40 GB）。
2. 已安装 Docker Engine（24+）与 Docker Compose v2 插件（`docker compose version`）。
3. 拉取仓库代码或仅同步部署所需文件（`docker-compose.prod.yml`、`docker/`、`scripts/`、`.env.example`）至 `/opt/geomix`：

```bash
mkdir -p /opt/geomix
cd /opt/geomix
cp .env.example .env
chmod 600 .env
```

### 2.2 编辑预发环境变量 `.env`

将以下必填安全项替换为随机生成的强密钥（切勿保留 `.env.example` 中的开发占位值，`deploy-staging.sh` 会自动拦截开发占位密码）：

```bash
# 生成随机密钥参考命令：openssl rand -hex 24
GHCR_OWNER=yexiu700
IMAGE_TAG=latest

POSTGRES_USER=geomix
POSTGRES_PASSWORD=<替换为随机强密码>
POSTGRES_DB=geomix

MINIO_ROOT_USER=geomix
MINIO_ROOT_PASSWORD=<替换为随机强密码>
STORAGE_DRIVER=s3
S3_BUCKET=geomix

JWT_ACCESS_SECRET=<替换为32位以上随机密钥>
JWT_REFRESH_SECRET=<替换为32位以上随机密钥>

WEB_ORIGIN=https://staging.example.com
NEXT_PUBLIC_API_BASE=/api/v1
AUTH_TRUST_PROXY=true
BILLING_MODE=SHADOW

# 若启用容器化 Nginx + HTTPS：
NGINX_SERVER_NAME=staging.example.com
# 内网预发测试若暂未签发正式证书，可设为 true 自动生成 30 天自签名证书
STAGING_SELF_SIGNED_TLS=false
```

### 2.3 执行预检与一键部署

1. **先执行 `--dry-run` 预检**（不触碰容器，仅验证 `.env` 完整性与执行计划）：

```bash
./scripts/deploy-staging.sh --with-tls --seed --dry-run
```

2. **正式执行预发一键部署**（首次部署加 `--seed` 初始化 GeoMix 2.0 3 项默认计费价目表与种子账号；后续升级无需重复加 `--seed`，但重复执行亦幂等安全）：

```bash
# 方式 A：使用容器化 Nginx + HTTPS（监听宿主机 80/443）
./scripts/deploy-staging.sh --with-tls --seed

# 方式 B：宿主机已有独立 Nginx / Caddy 反代（仅绑定 127.0.0.1:3000 与 127.0.0.1:3001）
./scripts/deploy-staging.sh --seed

# 方式 C：无 GHCR 访问时直接用宿主机源码构建镜像启动
./scripts/deploy-staging.sh --build-local --with-tls --seed
```

3. **部署后健康核验**：

```bash
curl -fsS http://127.0.0.1:3001/api/v1/health
docker compose -f docker-compose.prod.yml ps
```

## 3. Nginx 与 HTTPS 配置说明

仓库提供开箱即用的反向代理模板 [docker/nginx/geomix.conf.template](../docker/nginx/geomix.conf.template)，核心设计如下：

1. **HTTP 80 强制跳转与 ACME 验证**：
   - `/.well-known/acme-challenge/` 映射至 `${NGINX_ACME_WEBROOT:-./docker/nginx/certbot-www}`，支持 Let's Encrypt `certbot certonly --webroot` 免停机续期；
   - `/nginx-health` 供容器健康检查探针使用；
   - 其余 HTTP 流量全部 `301` 跳转至 `https://$host$request_uri`。
2. **HTTPS 443 安全基线**：
   - 仅启用 `TLSv1.2` 与 `TLSv1.3`，开启 `HTTP/2` 与 HSTS；
   - `client_max_body_size 110m;`，与单文件最大 100 MiB（`GALLERY_MAX_INPUT_BYTES=104857600`）对齐；
   - `/api/` 同时转发 `/api/v1/*` 与 `/api/v2/*` 至 `api:3001` 并透传 `X-Real-IP`、`X-Forwarded-For`、`X-Forwarded-Proto`，配合 `api` 容器默认 `AUTH_TRUST_PROXY=true`，确保按真实客户端 IP 独立计算验证码与登录失败限流桶。
3. **正式证书放置路径**：
   - 将证书链与私钥放到 `./docker/nginx/certs/fullchain.pem` 与 `./docker/nginx/certs/privkey.pem`（权限 `600`），然后执行：
     ```bash
     docker compose -f docker-compose.prod.yml --profile tls exec nginx nginx -s reload
     ```

## 4. 备份与灾难恢复演练步骤

### 4.1 日常备份执行与定时任务

[scripts/backup.sh](../scripts/backup.sh) 每次运行会在 `${BACKUP_DIR:-./backups}/geomix-backup-<UTC时间戳>/` 下生成：
- `postgres.dump`：`pg_dump -Fc` 自定义压缩格式逻辑全量备份（含 `pgvector` 扩展、租户数据、账本流水、品牌事实卡向量切片、诊断/文章记录与审计日志）；
- `minio-data.tar.gz`：`geomix_minio` 数据卷只读归档；
- `env.redacted`：自动脱敏掉所有 `*PASSWORD* / *SECRET* / *KEY* / *TOKEN*` 后的环境配置快照；
- `manifest.json` 与 `SHA256SUMS`：元信息与文件级 SHA-256 完整性校验码。

```bash
# 手动触发一次全量备份（保留最近 7 天）
./scripts/backup.sh --retention-days 7

# Crontab 每日凌晨 03:15（宿主机时区）自动备份示例：
# 15 3 * * * cd /opt/geomix && ./scripts/backup.sh >> /var/log/geomix-backup.log 2>&1
```

### 4.2 备份与恢复完整演练流程（可复现验收清单）

建议在每次大版本上线前，于独立预发机按以下 6 步完成一次闭环恢复演练：

1. **演练前基线记录**：
   - 登录预发工作台，记录当前演示租户的「品牌与双市场档案数量」「事实卡与品牌素材缩略图」「GEO 写作意见与文章总数」以及「剩余点数 / 点数流水条数」。
2. **生成演练备份包**：
   ```bash
   ./scripts/backup.sh --output-dir ./backups
   LATEST_BACKUP="$(ls -dt ./backups/geomix-backup-* | head -n 1)"
   ls -lh "${LATEST_BACKUP}"
   ```
3. **执行恢复预检（`--dry-run`）**：
   - 验证 `SHA256SUMS` 校验通过且恢复命令无误：
   ```bash
   ./scripts/restore.sh --backup-dir "${LATEST_BACKUP}" --dry-run
   ```
4. **模拟故障/误删场景**：
   - 在预发工作台手工删除一条测试 GEO 文章或上传/删除一张品牌素材，使当前状态偏离步骤 1 的基线。
5. **执行正式恢复**：
   ```bash
   ./scripts/restore.sh --backup-dir "${LATEST_BACKUP}" --yes
   ```
   - 脚本会自动校验 `SHA256SUMS` → 停止 `api / worker / web / minio` 写入 → `pg_restore --clean --if-exists` 恢复数据库 → 解压恢复 MinIO 数据卷并修正 `65532:65532` 权限 → 执行 `prisma migrate deploy` → 重启业务容器并轮询 `/api/v1/health`。
6. **恢复后核验标准**：
   - `/api/v1/health` 返回 HTTP 200；
   - 登录预发工作台核对：步骤 1 记录的「品牌档案、素材缩略图加载、GEO 写作意见与文章列表、点数与账本流水」与备份时刻完全一致；
   - 新发起一条可见度诊断或批量写作任务可正常被 `worker` 消费完成。

## 5. LLM 成本日报与模型费率配置

管理员登录后可在顶部导航进入 **「LLM成本日报」（`/admin/llm-costs`）**，接口为 `GET /api/v1/admin/llm-costs`：

- **统计口径**：统一按 `Asia/Shanghai`（UTC+8）自然日切分，支持近 7 / 14 / 30 天窗口、租户过滤、「是否包含开发占位假调用」开关及一键导出 CSV。
- **多维度拆解**：提供「按日明细」「按业务场景分布（事实卡提炼 / GEO 写作意见 / GEO 靶向写作 / GEO 局部改写 / 可见度裁判 / 生图提示词优化，并兼容展示历史 v1 场景键）」「按服务商与模型分布」「按租户排行」四张视图。
- **与钱包账本解耦**：LLM 成本日报统计的是平台侧上游模型 Token 消耗（单位：微元，1 元 = 1,000,000 微元），**不会修改任何租户的点数钱包或账本**，亦不会改变 `BILLING_MODE=SHADOW` 默认行为。
- **配置真实模型千 Token 单价**：
  - 未配置 `LLM_COST_RATES_JSON`（或为 `{}`）时，默认按占位微元估算并在页面顶部给出提示；
  - 接入真实模型后，可在 `.env` 中按 `provider/model`、`model`、`provider` 或通配符 `*` 配置每千输入/输出 Token 的微元单价（例如输入 2 元/百万 Token = `2000` 微元/千 Token，输出 8 元/百万 Token = `8000` 微元/千 Token）：
    ```env
    LLM_COST_RATES_JSON={"deepseek/deepseek-chat":{"inputMicroPer1k":2000,"outputMicroPer1k":8000},"*":{"inputMicroPer1k":1500,"outputMicroPer1k":6000}}
    ```
